# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

"Vacinas do Pet": an open-source, 100% local (no account, server, ads or analytics) Expo/React Native app that stores dog/cat vaccination records with proof photos and local reminders. The project is in the MVP phase; the design spec and implementation plan live in `docs/superpowers/specs/` and `docs/superpowers/plans/`. Check them before building new features, since much of the planned structure (see below) doesn't exist yet. `AGENTS.md` also applies (Expo docs must be fetched for the installed SDK version, which is 58, rather than trusting memory).

## Commands

```bash
npm test                          # Jest (jest-expo preset)
npx jest path/to/file.test.tsx    # single test file
npx jest -t "test name"           # single test by name
npm run lint                      # expo lint (ESLint flat config)
npm run typecheck                 # tsc --noEmit
npx expo start                    # dev server
npx expo run:android | run:ios    # build and run the dev client
```

CI (`.github/workflows/ci.yml`) runs `npm ci`, lint, typecheck and `npm test -- --ci`. Run all three before declaring work done.

- The app uses native modules, so it needs a development build; Expo Go does not work.
- `android/` and `ios/` are generated (CNG). Never edit them by hand; configure through `app.json` and config plugins.
- `jest/globalSetup.js` forces `TZ=America/Sao_Paulo` so date rules are tested against the UTC-3 local-day rollover. Don't depend on the machine's timezone in tests.

## Architecture

- Expo Router, routes in `src/app/` only; non-route code stays outside it. The `@/*` alias maps to `src/*`.
- Intended layering (from CONTRIBUTING.md): `src/domain/` pure business rules (no React, no DB; every new rule gets tests here), `src/data/` + `src/db/` SQLite access, `src/services/` photos/reminders/PDF/backup, `src/catalog/` per-country vaccine catalog, `src/i18n/`, `src/theme/`. Only `app`, `catalog`, `data`, `db`, `domain`, `i18n`, `services` (photos, reminders, PDF and backup so far) and `theme` exist so far.
- Screen tests live in `src/__tests__/app/`, mirroring the route path, because every file under `src/app/` becomes a route. Other tests sit next to the file they test (`src/domain/status.test.ts`).
- Routes: `index` (Meus pets), `archived`, `pets/new`, `pets/[petId]/` (`index` is the wallet, plus `edit` and `archive`), `vaccinations/new` (also the booster form, via `fromVaccinationId`), `vaccinations/[id]/` (`index` detail, `edit`) and `attachments/[id]` (photo viewer), `settings` and `backup`. A pet card opens its wallet; an archived pet's wallet and records are read-only. Screens for a missing pet or vaccination render `NotFound`.
- Data hooks sit next to `usePets.ts` in `src/data/` (`useVaccinations.ts`: `useWallet`, `useVaccinationDetail`); the pure assembling logic is in `wallet.ts`/`petSummaries.ts` and unit-tested. Shared UI is in `src/components/` (forms, `Button`, `ConfirmDialog`, `StatusBadge`, `NotFound`, label helpers `petLabels.ts`/`vaccinationLabels.ts`). Every write goes through `useGuardedAction`, with navigation outside the guarded write.
- Photos (`src/services/`): `photos.ts` asks for the permission only when used (camera; the library uses the system picker), never requests EXIF, resizes to at most 2048 px on the longer side (never up, `imageSize.ts`), re-encodes JPEG 0.8 with `expo-image-manipulator` and stores only that output as `<uuid>.jpg` in `photos/` (proof photos) or `pets/` (pet photo) under the document directory (`files.ts`: `photoUri`, `petPhotoUri`). Photos chosen before their owner exists (new vaccination, new or edited pet form) stay pending and are linked on save (`createVaccinationWithPhotos`; the pet row's `photoFile`); an unsaved form deletes them. A replaced pet photo gets a new file name, so the `expo-image` cache never shows the old one. Every deletion (`deletePet`, `deleteVaccination`, `deleteAttachment`) calls `deleteFiles(names)` after the database write; a failed file delete never fails the action, and `removeOrphanFiles(db)` sweeps leftovers once at app start. Max 3 photos per record; an archived pet's photos are view-only. The viewer is `attachments/[id]` (pinch/pan with gesture-handler + reanimated, `ZoomableImage`). Native modules are mocked in service tests (`fakeFileSystem.ts`); the zoom gestures only run on a device.
- Reminders: local notifications only (`expo-notifications`, plugin configured with `enableRemoteNotifications: false`; no push, no network). `planReminders` (`domain/reminders.ts`, pure) picks one reminder per `reminder_offsets_days` value for each current record of an active pet with a next dose and `remindersEnabled`, nearest first, at most 50; the service passes `catalogMatcher` as `matcherFor`. `services/reminders.ts`: `syncReminders()` cancels all and schedules the plan at 09:00 local (`reminderFireDate`, DATE trigger, Android channel `reminders`), never throws; when today's 09:00 has passed the plan starts tomorrow. The single trigger is `useReminderSync` (mounted as `ReminderSync` in `_layout.tsx` after migrations): it calls `requestReminderSync` (serialized by `serialRunner.ts`, last request wins) at start and on any pets, vaccinations or settings change, so screens, backup import and the like never call `syncReminders` themselves. `ensureNotificationPermission()` asks only while the permission is undetermined and runs after the first save of a record with a next dose (`VaccinationForm`). The detail screen's `RemindersSection` shows the dates, the switch (a guarded write resending every field) and the "off in the system" notice.
- PDF (`src/services/`): `pdf.ts` is pure (`buildCardHtml`: escapes every user string, no script, no remote resource, B&W-safe CSS, sorts newest first itself; `pdfFileName`); its texts come in as `labels` built once by `pdfLabels.ts` from the `pdf.*` i18n keys. `exportPdf.ts` (`exportPetPdf`) reads the pet, records and photos (base64 data URIs; an unreadable photo becomes a line in the PDF), prints with `expo-print` (A4), renames the file to `carteira-<pet>-<date>.pdf` in the cache, opens `expo-sharing`; the shared file stays in the cache (the receiver may still be reading it) and the next export deletes earlier `carteira-*.pdf`. Memory is unbounded by design: every proof photo is embedded as base64 in one HTML string, with no cap (dropping photos would be a product decision). `useExportPdf` drives the wallet's "Exportar PDF" button (shown for active and archived pets with at least one record). `expo-print` and `expo-sharing` are native: a new development build is needed.
- Backup (`src/services/backup/`): `schema.ts` is the single Zod definition of `data.json` (strict; snake_case column names; `<uuid>.jpg` file names only); `rows.ts` holds the two inverse mappings between app rows and backup rows; `buildData.ts` (`buildBackupData`) reads the database; `export.ts` (`exportBackup`) stages `data.json`, `photos/` and `pets/` in the cache, zips with `react-native-zip-archive` (native: new development build), opens `expo-sharing`, then stores `last_backup_at`; the zip stays in the cache and the next export deletes earlier ones; a missing photo is left out and counted. `shouldWarnBackup` (`domain/backupWarning.ts`, local calendar days) drives `BackupBanner` on Meus pets; `useBackupStatus` feeds the banner and the `backup` screen; `useExportAction` is the shared lock/busy/error hook behind `useExportPdf` and the backup button. Import is a later task.
- Settings screen (`settings.tsx`, linked from Meus pets): `due_soon_days` (1-365) and `reminder_offsets_days` (0-365, unique, at least one), validated by `domain/settingsInput.ts`; also version, license, repository link (opened with `Linking`) and the declaratory notice.
- Domain rules (`src/domain/`):
  - Dates: calendar dates are `IsoDate` text (`YYYY-MM-DD`); instants are ISO 8601 UTC strings. Get "today" with `todayLocal()` (device local date), never `new Date().toISOString().slice(0, 10)`, which is a day ahead after 21:00 in UTC-3. Do date math only through `addDays`/`diffDays` (`dates.ts`), which compute at 12:00 UTC so DST can't shift a day.
  - Status (`status.ts`): `getStatus(nextDueOn, today, dueSoonDays)` → `overdue` from the day after the due date, `due_soon` from today up to `dueSoonDays` days ahead (inclusive), otherwise `ok` (also when there is no next dose). `worstStatus` picks the worst for a pet's badge.
  - Same vaccine (`current.ts`): always compare vaccines with `vaccineKey(v, matchCatalog?)`, never by raw name. Order: the catalog id; else the catalog item that the free name matches (via `matchCatalog`, the matcher for the pet's species, receiving the name from `normalizeVaccineName()`: no accents, lowercase, inner and surrounding spaces collapsed); else `name:` plus the normalized name. "gripe canina" ≠ "gripecanina". `src/domain/` never imports `src/catalog/`; the matcher is passed in. `splitCurrent(list, matchCatalog?)` returns the current record per vaccine (latest `appliedOn`, ties broken by latest `createdAt`) and the previous ones, both in input order; only current records get status badges and reminders.
  - `suggestNextDue(appliedOn, boosterIntervalDays)` (`nextDose.ts`) adds days, not years.
- Catalog (`src/catalog/`): `br.json` holds the vaccines (ids are permanent; names are Portuguese user data); `listCatalog(species)`, `findCatalogVaccine(id)` and `catalogMatcher(species)` read it. Pass `catalogMatcher(pet.species)` as the `matchCatalog` argument of `vaccineKey`/`splitCurrent`.
- i18n: `src/i18n/index.ts` creates an isolated i18next instance (pt-BR only for now) and is imported first in `_layout.tsx`. All UI strings go in `src/i18n/pt-BR.json`; `src/__tests__/app/no-hardcoded-text.test.ts` fails on hardcoded text in screens.
- Theme: `useTheme()` from `@/theme` returns the palette for the current color scheme plus spacing/radius/typography tokens. Status colors (`ok`, `dueSoon`, `overdue`, `neutral`) are semantic. Don't hardcode colors in components.
- `src/__tests__/projectConfig.test.ts` and `environment.test.ts` guard project configuration, so config changes (app.json, package.json) may need those tests updated.

## Conventions

- Code, identifiers, DB tables, files and commit messages are in English, including test names (`describe`/`it`) and code comments; the UI and issues are in Portuguese. Test data may stay in Portuguese when it is real input (vaccine names like "Antirrábica").
- Write non-ASCII ranges in regexes as escapes (`/[\u0300-\u036f]/`), never as the literal characters, which are invisible in editors and reviews.
- Conventional Commits: `<type>(<scope>): <imperative description in English>` (used to generate versions/changelog).
